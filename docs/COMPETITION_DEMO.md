## Technical explanation judges can inspect

The local document classifier is a reproducibly trained TF-IDF/logistic model, with a separately authored fictional evaluation set and abstention thresholds. It supplies a ranked suggestion; source-linked rules and explicit resident confirmation supply the preparation checks. Python owns training/evaluation and source maintenance, TypeScript owns the typed domain and BM25 public retrieval, SQL owns account permissions and atomic save/quota records, and JavaScript/HTML/CSS supply the browser interface. Anchor does not use a neural document model, ONNX, or Rust in this release. Do not present language percentages as proof of complexity.

Show the source-versioned public knowledge library, browser/server input contract, editable PDF mapping checks and an actual test report from the release being demonstrated. Mention Gemini as the underlying explanation provider in technical materials where relevant, while the product's user-facing assistant is Anchor. Explain that the free-tier cloud path accepts bounded public topic identifiers rather than private document text.

For impact, distinguish the observed problem, designed benefit, synthetic evaluation and measured resident outcomes. Use [the study kit](USABILITY_STUDY.md) to collect real feedback. Until then, say that the usability study has not been conducted. Do not claim saved benefit dollars, retained benefits, partnerships or agency endorsements without evidence.

## Submission materials

Prepare the public [repository](https://github.com/JaivardhanSamadhiya/Anchor), working [demo link](https://jaivardhansamadhiya.github.io/Anchor/), video, three screenshots, architecture explanation, source list and exact release commit. Describe existing code and new work accurately for each competition, and complete required registration or track forms yourself.

Use the relevant live rules when submitting:

- [Congressional App Challenge rules](https://www.congressionalappchallenge.us/students/rules/): verify eligibility, team membership, originality, submission details and the district's specific instructions. Anchor's benefits-access purpose addresses the district topic provided for this project.
- [WarriorHacks rules](https://warriorhacks-2-0.devpost.com/rules) and its linked [Code of Conduct](https://docs.google.com/document/d/1g-o21ab84v7vmqpqpRk_RLHb8hrAFNw52n1-SQg9Eds/edit): describe the Anchor baseline and the changes made for the event, follow its reuse/disclosure requirements and submit the hackathon track selection, repository, screenshots and 2-3-minute video as requested.
- [Neighborhood Hacks rules](https://neighborhoodhacks.org/rules/): the published rules require new work during October 16-23, 2026, prohibit pre-existing projects and require AI-tool disclosure. Current Anchor is a pre-existing project; upgrades do not make it a qualifying new entry. Plan a fresh standalone event project unless the organizers explicitly provide a different ruling. A 2-6-minute video and public repository are required for an eligible entry.

Rules and deadlines should be rechecked on the live competition pages at submission. An exception granted for one competition does not automatically apply to another. Preserve any organizer clarification and follow it accurately.
